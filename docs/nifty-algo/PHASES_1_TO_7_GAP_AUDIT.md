# Phases 1–7 Gap Audit

Historical phase audit. For the current 23 November corrective working-tree
review and test results, see [READINESS_REPORT.md](READINESS_REPORT.md).
The five features are now partially implemented; the final "inactive" statement
below describes the earlier checkpoint only. Current feature limitations are
listed in [ADVANCED_FEATURES_READINESS.md](ADVANCED_FEATURES_READINESS.md).

Working audit of the NIFTY paper-trading subsystem across Phases 1–7.
Each finding is classified: **FIXED** (defect confirmed and remediated with
regression tests), **VERIFIED** (audited, no defect found), or **DEFERRED**
(real gap, intentionally out of scope).

Offline tests are not proof of production readiness. Live execution stays
hard-blocked until broker auth, market-data quality, protective-order
acceptance, fill reconciliation, and deployment prerequisites are verified
independently against a real session.

## Phase 1 — Admission and fill risk controls

| # | Finding | Verdict | Evidence / fix |
|---|---------|---------|----------------|
| P1-01 | Config limits could be weakened below strategy floors | **FIXED** | `StrategyConfig` previously allowed `max_planned_loss`, `min_projected_net_reward`, `max_hold_minutes`, `monthly_loss_limit`, `virtual_capital`, window times and trailing distance to be relaxed past safe bounds. Bounded validators added in `services/nifty_algo/config.py`; 9 boundary tests in `test/test_nifty_algo_gap_p1.py`. Follow-on defect found and fixed: `virtual_capital` was a `Literal[Decimal]` that failed JSON round-trip (`model_dump(mode="json")` emits `"20000"` string) — every persisted config failed `model_validate`, so `ensure_user` paused the account permanently (ENTRIES_PAUSED). Now a bounded non-Literal field that survives round-trip. |
| P1-02 | Fill did not revalidate ₹350 projected net reward at the actual fill price | **FIXED** | `fill()` recomputed `target_price` at the fill price but never re-checked `min_projected_net_reward`. Added `NET_REWARD_BELOW_MINIMUM` rejection at `database/nifty_algo_db.py:1738`. Test: `test_fill_revalidates_reward_at_actual_fill_price`. |
| P1-03 | Fill observation skipped liquidity + moneyness checks | **FIXED** | Fill-time observation never re-checked crossed book, spread, volume, bid presence, or OTM transition. Added `LIQUIDITY_LOST` (spread/volume/crossed/missing-bid) and `OTM_PROHIBITED` (spot-reference moneyness reclassification; unavailable spot fails closed, order stays PENDING) at `nifty_algo_db.py:1719-1733`. Tests: crossed-book, widened-spread, missing-bid, collapsed-volume, OTM, unavailable-spot cases. |
| P1-04 | Fills must be causally tied to the observed depth snapshot | **VERIFIED** | Fill derives price/fees from the same observation hash (`token:source_time:side`) and reserves depth via `NiftyDepthUse`; `daily_entry_counted` payload flag keeps reservation idempotent across retry. |
| P1-05 | Stop-exit price could go nonpositive on low-premium fills | **FIXED** | `stop_exit = initial_stop − tick×slippage_ticks` had no validity check. Added `STOP_PRICE_INVALID` rejection at `nifty_algo_db.py:1717` (defense-in-depth — `initial_protection` already raises → `PROTECTION_TICK_INVALID` on degenerate targets). Key structural finding: `PROTECTION_TICK_INVALID` is unreachable through `admit()` — any premium low enough to break the tick math necessarily fails `LIQUIDITY_UNAVAILABLE` first (~5000 bps spread on a ₹0.05 grid). Tests assert honest gate ordering: `admit()` → `LIQUIDITY_UNAVAILABLE`; `plan_entry()` directly → `PROTECTION_TICK_INVALID`. No pending residue after rejection. |
| P1-06 | Ledger races on funds/entries under concurrent fills | **VERIFIED** | `fill()` runs inside the user lock; re-checks planned loss vs `reserved_risk`, cost vs `account.available`/`reserved_capital`, daily entries, mode reasons, and `configuration_id` match before committing. |

## Phase 2 — Protection invariants and unfilled exits

| # | Finding | Verdict | Evidence |
|---|---------|---------|----------|
| P2-01 | Protection state must ratchet monotonically and latch exit reasons | **VERIFIED** | `observe_bid` computes `stop_price = max(initial, previous, trailing, floor)` — never lowers the stop; `exit_reason` latches and persists via `observe_position`; all stops `ceiling_tick`-aligned; `mandatory_exit_reason` precedence: MAX_HOLD > TECHNICAL_INVALIDATION > SESSION_EXIT > OPERATOR_CLOSE > discretionary. `PROFIT_FLOOR_UNREPRESENTABLE` forces exit when the floor can't be ticked; `PROFIT_FLOOR_GAP` honestly records fills that undercut floor net. |
| P2-02 | Unfilled/failed exits must stay latched and retryable | **VERIFIED** | `monitor_exits` re-issues a SELL each cycle when no pending exit exists, with deterministic identity `exit:{entry_order_id}:{attempts}`; `OrderRefused` swallowed as concurrency guard; pending check prevents duplicates; `expire_pending` clears dead intents so retry proceeds. SELL fill is gated only by `UNCOVERED_SELL` — never by reward/liquidity gates (all entry gates sit inside `if order.side == "BUY":`). Observation (not a defect): no operator escalation after N failed exit attempts — retries are unbounded by design, and a latched protective exit is safer than giving up. |

## Phase 3 — Calendar, sessions, cooldowns

| # | Finding | Verdict | Evidence |
|---|---------|---------|----------|
| P3-01 | Session authority must require an operator-approved NFO calendar | **VERIFIED** | `nifty_session` returns `CALENDAR_UNAPPROVED` when no `APPROVED` version exists; executor refuses at `paper_executor.py:264`. `approve_calendar` (`nifty_algo_db.py:485`) requires DRAFT status, matching `confirmed_year`/`confirmed_segment`, `segment == "NFO"`, and rejects any `ambiguous` entry — all under the per-user lock. Prior APPROVED version is superseded; approval triggers `resolve_cooldowns(recompute=True)`. |
| P3-02 | Special/unknown sessions and unknown timings must fail closed | **VERIFIED** | `get_special_session` → `SPECIAL_SESSION_DISABLED`; weekend/holiday non-trading; `TRADING` with `window=None` (no timing configured) yields `entry_session_open=False` (`paper_executor.py:271-275`) → entries refused as session-closed. `next_eligible_session` raises `CALENDAR_UNAPPROVED` when the candidate year's calendar is unapproved. |
| P3-03 | Calendar parser must surface ambiguity, never silently fix it | **VERIFIED** | `calendar_import.py` flags `DATE_INVALID`, `DATE_FORMAT_UNCLEAR`, `DATE_OUTSIDE_CIRCULAR_YEAR`, `WEEKDAY_MISMATCH`, `DUPLICATE_DATE`, `MULTIPLE_YEARS` as `ambiguous` → approval rejects. `WEEKEND_HOLIDAY` is a recorded issue but non-blocking (weekends are non-trading anyway). PDF requires NFO segment confirmation; size capped at 2 MB; non-PDF/non-UTF-8 rejected. |
| P3-04 | Draft edits and weekday fields must be recomputed, not trusted | **VERIFIED** | `recompute_entries` re-derives `weekday` from the parsed date and re-flags every integrity issue; `update_draft_entries` persists only recomputed entries under the lock, so operator edits cannot smuggle wrong weekdays or drop ambiguity flags. |
| P3-05 | Loss cooldowns must schedule via the approved calendar and resolve fail-closed; monthly locks must latch under the lock | **VERIFIED** | `_schedule_cooldown` writes `cooldown_session=None`; `resolve_cooldowns` assigns the next eligible session via `next_eligible_session` (bounded 370-day scan); unresolved ⇒ `COOLDOWN_UNRESOLVED` blocks entries fail-closed until a calendar resolves it. `entry_locks` latches `MONTHLY_LOSS_LOCKED`/`MONTHLY_PROFIT_LOCKED` and returns `*_LOCK` reasons, checked under the user lock in both `admit_order` and `fill`. Observations (not defects): a future-scheduled cooldown also blocks the loss-day remainder — harmless since the daily loss lock already covers it; `COOLDOWN_UNRESOLVED` persists until the next year's calendar is approved — correct fail-closed behavior that should be operator-visible in setup docs. |

## Phase 4 — Shadow lifecycle and opportunity P&L

| # | Finding | Verdict | Evidence |
|---|---------|---------|----------|
| P4-01 | Shadow entries must be signal-gated, idempotent, and lock-serialized | **VERIFIED** | `open_independent` requires a qualifying signal (eligible, CE/PE, `config_id` match, confidence-method match, ≤30 s freshness), session open + `SHADOW_ENTRY_WINDOW` + cooldowns (`shadow.py:49-94`); `open_shadow` re-checks under `self._lock` — `SHADOW_ACTIVE`, `PRIMARY_ACTIVE`, `PRIMARY_PENDING`, entry window, cooldown reasons — and returns the original row on `shadow_key` replay or `IntegrityError` (`nifty_algo_db.py:2539-2624`). Monthly locks intentionally do not block shadows (non-capital research path). |
| P4-02 | Opportunity P&L must be honestly modeled and never double-counted | **VERIFIED** | `_close_shadow` computes `gross`/`net` via `modeled_exit_net` at `bid − tick×slippage`; `UNAVAILABLE` leaves net `None` → excluded from the ledger sum (`net.is_not(None)`). `shadow_ledger` compounds only `additive=1` (independent) nets into equity; mirror nets are reported separately as `mirror_realized_net` (`nifty_algo_db.py:2876-2898`). |
| P4-03 | Non-depth exits must be labeled, not presented as modeled fills | **VERIFIED** | Valuation labels: `DEPTH_MODEL` (fillable bid + `bid_size ≥ qty` + positive modeled fill), `LAST_BID` (post-close settle at last observed bid), `PRIMARY_JOURNAL` (mirror closed from `NiftyTrade` journal), `UNAVAILABLE`, `PREEMPTED_BY_ACTUAL_MIRROR` event. `LAST_BID` is only updated on `_observable`-valid quotes, so a stale bid can't silently become an exit price. |
| P4-04 | Shadow observations must obey the same causality/freshness rules as primary | **VERIFIED** | `observe_shadow` gates every quote through `_observable` (2035-2046): token match, bid + size, `source_time ≤ received_time ≤ now`, age ≤ `quote_max_age`, `source_time ≥ opened_at`, strictly newer than `last_source_time` — monotonic consumption, no replay. Reuses `observe_bid`/`mandatory_exit_reason`; stop-ratchet regression raises `ValueError` (2701-2702). `sync_shadow_mirrors` double-checks under lock, dedups by `mirror:{entry_order_id}`, preempts an active independent at `LAST_BID`, and links the mirror by `primary_entry_order_id`. Nothing in the shadow path transmits orders. |

## Phase 5 — Live hard-block, credentials, mode/recovery

| # | Finding | Verdict | Evidence |
|---|---------|---------|----------|
| P5-01 | Live execution must be hard-blocked; no path may transmit a real order | **VERIFIED** | Three independent layers: (1) executor routes a BUY through `LIVE_ADAPTER.submit(intent)` when `_live_mode()` — the stub raises `OrderRefused([LIVE_NOT_READY])` before any plan, order row or broker import (`paper_executor.py:182-186`; `trading_mode.py:46-69`); (2) `change_mode` appends `LIVE_NOT_READY` to any LIVE request even if `evaluate` returns no codes, and Live mode can therefore never persist (`nifty_algo_db.py:938-939`); (3) the stub owns no transport — `reachable()` is `False`, `readiness()` returns five unverified codes, `submit` refuses before any broker call. `live_readiness` adds `LIVE_NOT_READY` unconditionally. Shadow/research paths persist rows only — nothing in `shadow.py`/`research.py` imports a broker adapter. |
| P5-02 | Broker secrets must never leave the subsystem or reach logs | **VERIFIED** | `read_broker_facts` is read-only and never decrypts the stored token; `_masked` is the single masking point converting secrets to presence booleans — only `broker`, `broker_name`, `key_source` and `*_present/configured` booleans leave (`trading_mode.py:96-138`). A failed read logs `type(error).__name__` only — never the message, which could echo a connection string or credential — and returns a generic `_UNAVAILABLE` dict (141-148). Module docstring states: "never a character or the length of a token, key or secret." |
| P5-03 | Mode switching must be atomic, audited and restart-safe; exposure must gate transitions | **VERIFIED** | `change_mode` is a compare-and-set under `self._lock`: revision mismatch or `rowcount != 1` raises `StateConflict`; refusals are audited as `mode_change_refused` events with actor/revision/exposure/readiness snapshot and change nothing; successes append a bounded `history` entry (`nifty_algo_db.py:920-981`). `mode_refusals` blocks any transition with `OPEN_EXPOSURE` unless it's a no-op (`trading_mode.py:186-192`). `trading_mode()` lazily creates the row as PAPER with an `IntegrityError` read-back — post-restart the mode is whatever was last persisted, and only PAPER can persist. `_live_mode()` reads the store per admit, so a mode can never be smuggled in via payload. Blueprint validates the body strictly (`mode∈MODES`, `revision` int ≥1, `acknowledged` bool, exact key subset), sets `actor=session["user"]`, and returns 409 with the refusal codes (`blueprints/nifty_algo.py:263-302`). |

## Phase 6 — Reports: catch-up, gaps, FAILED recovery, content, pagination, SMTP

| # | Finding | Verdict | Evidence |
|---|---------|---------|----------|
| P6-01 | Missed periods must be caught up on restart without duplication or unbounded work | **VERIFIED** | `due_periods` walks `max(user_since, today − LOOKBACK_DAYS=7)` → today emitting DAILY per closed TRADING session; `ensure_report` is idempotent via `UniqueConstraint(user_id, kind, period_key)` + `IntegrityError` read-back (`nifty_algo_db.py:3063-3101`, `315`); work is capped at `GENERATIONS_PER_TICK=3`/`SENDS_PER_TICK=1` (`reports.py:46-56`). |
| P6-02 | Months with missing/unapproved calendars must not produce wrong last-session reports | **VERIFIED** | `due_periods` skips any month whose `approved_calendar_version` is `None` — "an unapproved calendar leaves the month's last session undecidable" — and emits MONTH_END only when the last TRADING session exists and is past its close (`reports.py:598-611`). MILESTONE periods derive from persisted `loss_locked_at`/`profit_locked_at`, not recomputation (612-616). |
| P6-03 | FAILED/interrupted generation and delivery must recover deterministically, never double-send | **VERIFIED** | Generation: exception → `fail_report_generation` (`type(exc).__name__` only); `reports_needing_generation` reselects PENDING∨FAILED under `attempts < 3`. Delivery: `claim_report_delivery` is a single-statement CAS on `claim_token IS NULL ∧ claimed_until IS NULL ∧ generation_status=GENERATED` — exactly one worker wins a uuid4 token + 300 s lease (`nifty_algo_db.py:3215-3242`). `fail_interrupted_deliveries` converts expired leases to `FAILED`/`DELIVERY_OUTCOME_UNKNOWN` — conservative: SMTP may have accepted before the crash (3327-3345). | P6-06 | SMTP failures must degrade gracefully without secrets in logs and without marking unattempted sends as failed | **VERIFIED** | Settings-read failure leaves rows PENDING — "a failed settings read is not 'SMTP not configured'" — and logs `type(exc).__name__` only (`reports.py:711-717`). ## Phase 7 — Hardening sweep: runner lease, scheduler, recovery, transport canary

| # | Finding | Verdict | Evidence |
|---|---------|---------|----------|
| P7-01 | Scheduler jobs must be named, coalesced, bounded to one instance and cleanly removed | **VERIFIED** | Three jobs per user — `nifty-paper:{sha24}:protect` (1 s), `:entries` (5 s), `:reports` (60 s) — all `max_instances=1`, `coalesce=True`, `replace_existing=True`; a failed registration rolls back already-added jobs in reverse order (`runner.py:586-625`; asserted in `test_nifty_algo_pipeline.py:324-328`). Shutdown hook removes jobs **before** `runner.close()` and clears the registry, registered once via `register_shutdown_hook(early=True, budget_s=5)` (`runner.py:640-652`). Attach is idempotent under `_ATTACH_LOCKS.hold` + `user_id in runners` (552-561). |
| P7-02 | A delayed heartbeat must not shorten the owner lease; a closed runner must not recreate it | **VERIFIED** | `claim_runner` is a CAS under `self._lock`: refuses while another owner holds an unexpired lease; for the same owner `expiry = max(now + seconds, existing expiry)` — extension only, never shortening (`nifty_algo_db.py:767-786`). `release_runner` deletes only `row.owner == owner` — a stale runner cannot evict a successor (788-793). `_lease()` returns `False` once `self.closed`, so a closed runner cannot recreate a lease (`runner.py:72-86`). |
| P7-03 | Fills and the Start control must reject dead-runner / stale-lease actors | **VERIFIED** | `fill()` refuses when `order.payload.runner_owner` no longer matches the live lease or its expiry precedes `order.created_at` (`nifty_algo_db.py:1379-1384`). The `start` control requires a live lease, `entries_ready`, `lease.configuration_id == state.configuration_id`, `account.reconciled` and no kill/daily lock — all under the user lock and the revision CAS (696-720). |
| P7-04 | No order-transport or broker write path may exist anywhere in the subsystem | **VERIFIED** | Grep for `place_order|orderbook|placeorder|smart_order|basket|modify_order|cancel_order` across `services/nifty_algo/` returns zero matches after excluding internal identifiers — the only outbound path is `LiveAdapterStub.submit`, which always refuses. `runner.reports()` logs `type(exc).__name__` only; `scoped_reports` wraps settings/user reads in `session_cleanup()` at the scheduler boundary (`runner.py:530-538, 579-584`). |
| P7-05 | Native-client replacement and callbacks must not leak subscriptions across runner restarts | **VERIFIED** | `close()` unregisters the adopted `cache_callback` from the shared client, releases the lease and clears `owned_subscriptions` — replacement clients keep their own subscriptions because only the recorded callback is removed (`runner.py:544-549`, TESTING.md "Final recovery and event checks"). |

### Sweep observations (design, not defects)
- Report generation claims are not leased like delivery claims: `reports_needing_generation` can return the same PENDING row to two concurrent ticks, so `generate()` could render the same PDF twice; `os.replace` and the identical content hash make this idempotent and harmless. Delivery (the side-effecting path) is the one with the strict CAS.
- Uncertain SMTP outcomes become `FAILED`/`DELIVERY_OUTCOME_UNKNOWN` rather than retried — a deliberate no-duplicate-mail choice requiring operator re-enqueue via retry semantics elsewhere.

## Overall verdict

The four Phase-1 defects (P1-01, P1-02, P1-03, P1-05) are remediated; the remaining findings were verified by code inspection. The fill-time index reader now requires a native source observation with a finite positive LTP and causal, fresh source/receipt timestamps. Display-only data cannot rescue an invalid source; the BUY remains pending until valid data arrives or its intent expires.

The current Windows regression matrix passed 317 tests (exit 0); a subsequent malformed-LTP case is recorded separately in [TESTING.md](TESTING.md). Earlier Linux evidence does not cover this remediation. Docker's Linux engine is unavailable, so mandatory Linux eventlet/gthread verification, commit and push remain blocked.

Deferred features (Smart Selector, Safety Center, Analytics, Replay Lab, Discord Bot) remain inactive. Offline verification only: forward paper observation, real SMTP delivery, broker authentication, historical replay and production-worker rehearsal remain separate operator acceptance work.
